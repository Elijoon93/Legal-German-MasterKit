# Legal German MasterKit — Locked Project Baseline

**Owner / product direction:** Saeed Dahiri Dehnavi  
**Locked on:** 2026-07-28  
**Applies from:** v8.7 onward

## Non-negotiable acceptance rules

1. No navigation item may exist without a real view, real data, and a usable workflow.
2. A commit is not a public release. Public runtime acceptance requires a visible version badge and evidence from the deployed URL.
3. Mobile and tablet acceptance covers widths up to and including 1024px, with explicit iPhone/iPad/Safari checks.
4. Existing user state must not be reset during upgrades. New state must be additive and migration-safe.
5. Every phase requires measurable content counts, syntax checks, PWA/cache checks, and a release manifest.
6. Empty shells, decorative cards, placeholder headings, inflated counts, and unverifiable academic claims are rejected.
7. Official university requirements and legal materials must link to authoritative sources and include a last-checked date where practical.
8. Exact professor/chair instructions, Moodle materials, Friedolin listings, and the current official PDF always override generic program guidance.
9. The visual and information architecture may learn from Pflege Deutsch Pro, but no nursing-domain data may enter this legal product.
10. Final status is prohibited until real-device acceptance, backup/restore roundtrip, offline/update behavior, and critical workflow tests pass.

## Required product character

- Persian-first RTL interface with correct German LTR/bidi behavior.
- Serious academic/legal visual language; no childish iconography or game-like presentation.
- Content-first development: terminology, sentences, readings, cases, statutes, judgments, research workflows, and assessments.
- Each course must connect doctrine → language → source → case → writing → assessment → evidence.
- Academic-submission tooling must distinguish between an automated structural check and an official faculty/supervisor requirement.

## Release gates

SOURCE → SYNTAX → DATA COUNTS → STATE MIGRATION → RUNTIME → CORRECT ROUTE → RESPONSIVE → PWA UPDATE → PUBLIC VERSION BADGE → REAL DEVICE EVIDENCE

A release that fails any gate remains **Not Final**.
